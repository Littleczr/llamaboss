Getting started

What LlamaBoss does

LlamaBoss is designed for people who want an AI assistant that can do useful local work without turning every task into a cloud workflow. It keeps the normal chat experience simple, while advanced actions run through controlled tools and approval cards.

1

Load a local model

Use the model manager/downloader flow to select a GGUF model and start a llama.cpp server session.

2

Chat naturally

Ask normal questions, attach files, or request work like reading source, creating reports, or listing directories.

3

Let tools do the work

The agent loop routes safe inspection tools automatically and pauses for approval before broader local automation.

4

Use projects and skills

Attach work to a project, keep project notes, and create reusable skills for repeatable workflows.

Architecture

How the app is put together

The source has matured into a clear set of subsystems. The main app remains native C++, while specialized work is routed into constrained helpers.

Native app shell

LlamaBoss.cpp, ui_builder, chat_display, conversation_sidebar, and theme drive the wxWidgets desktop experience.

Model runtime

server_manager, model_manager, model_switcher, and model_downloader manage local model selection, llama-server launch, readiness, and model display labels.

Chat pipeline

chat_client sends requests, chat_history stores messages and tool replies, and tool_protocol detects XML vs native tool-call support.

Agent loop

agent_controller parses assistant tool calls, dispatches tools, appends results, and continues until the model stops or a safety condition ends the loop.

Tool registry

tool_router centralizes tool specs, schemas, validation, dispatch, and safety metadata so slash commands and agent calls share one path.

Projects & skills

project_manager, skill_prompt_builder, and skill_authoring_support support project context, notes, workflows, and reusable task instructions.

Safety model

Useful tools, controlled blast radius.

LlamaBoss is not trying to hide powerful behavior. It separates low-risk inspection from broader automation, then gives the user a review point before risky changes happen.

Read-only inspection can auto-run when the command/tool is clearly safe.

PowerShell is classified into auto-run read-only commands, approval-required commands, or rejected malformed commands.

File mutations are scoped to the conversation workspace or active project root.

Python helpers are constrained to fixed helpers first, with script creation and package installs gated by approval.

The agent loop has guardrails including iteration caps, malformed-call limits, repeated-tool detection, and cancel/approval states.

Common workflows

Good first documentation examples

Source code review

Ask LlamaBoss to list, read, grep, and summarize files from a local repo. Mutating edits should pause for approval.

Excel/report generation

Use structured workbook creation for staffing reports, KPI sheets, CSV conversions, and formatted Excel output.

PDF/DOCX workflows

Extract text, inspect PDF forms, fill controlled form fields, and generate readable artifacts for review.

Project memory

Attach a chat to a project so instructions, notes, sources, and workflows stay anchored to one workspace.

Skills

Switch models, detect tool protocols, and compare how small local models behave on practical work.
